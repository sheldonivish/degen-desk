# Memecoin trenches report (v4: short picks)

The owner asked (Oct 9, 2026) for a short, clean "what to buy" list with a conviction score and no fluff, instead of the long digest. The report is now generated by `picks.py`; don't hand-write sentiment, majors commentary, accumulating/fading or most-mentioned sections. Every number must come from the run data; never write a figure you can't point to. Picks are data-scored candidates, not orders: they never trigger a trade (see `memecoin-trading-guardrails`).

Working files: `/workspace/trenches/` (`fetch.py`, `calls.jsonl`, `dex_cache.json`, `runs/`, `README.md`, `telegram/`). Research detail: the `memecoin-onchain-research` skill. Execution rules: the `memecoin-trading-guardrails` skill. Telegram delivery: the `telegram-report-delivery` skill.
Anything beyond the report (other chains, perps, prediction markets, launches, media, dev): see `degen-desk-skill-map`, which routes to the `clawd-<category>` router skills and the sub-skills inside them.

## Inputs
- 1–5 curated X list IDs of traders (stored in the routine or memory, not in this skill).
- The built-in `x` tools (free tier, ~30 calls/min and 1000/day). Don't use a paid X connector unless the built-in tools are missing.
- Python 3 stdlib only. No API keys and no wallet needed (a Telegram bot token only if Telegram delivery is set up).

## Each run

1. **Read X: one `x.search_posts_all` call per list**
   - `query`: `list:<id> -is:retweet -is:reply`
   - `max_results`: 25, `sort_order`: `recency`
   - `start_time`: now − 70 min (UTC ISO). The window overlaps the previous run by 10 min, so nothing falls between runs.
   - `expansions`: `author_id`. `user.fields`: `username,name`
   - `post.fields`: `created_at,author_id,public_metrics,referenced_tweets,entities,edit_history_tweet_ids`
   - If a list returns exactly 25, it hit the cap. Re-query it as two halves of the window (`start_time`/`end_time`) and keep both responses.
2. **Save the raw responses** to `runs/raw_<YYYYMMDD_HHMM>.json`:
   `{"window": {"start": ISO, "end": ISO}, "lists": {"<list_id>": [<response>, ...]}}`
3. **Build:** `python3 fetch.py build --raw runs/raw_<stamp>.json`. The build:
   - dedupes across lists and edited posts (keeps the newest id in `edit_history_tweet_ids`);
   - drops replies/RTs and off-topic posts (no cashtag, no CA, no market keyword). The dropped list is printed (not used in the v4 report);
   - extracts CAs (`chain:CA` as X renders them, plus bare EVM/Solana addresses);
   - resolves each CA on DexScreener: ticker, chain, MC (FDV if MC is missing), liquidity, 1h/24h change, oldest pair age, falling back to the labelled last-good cache on rate limits;
   - gets BTC/ETH/SOL from Hyperliquid marks, falling back to CoinGecko and then Coinbase spot, labelled with the source;
   - enriches each CA: pump.fun bonding-curve status or graduation, Musebook decide snapshot (Solana only), RugCheck (Solana) or GoPlus (EVM), plus heuristic risk flags. `--no-enrich` skips this;
   - upserts every CA mention into `calls.jsonl` (idempotent; the first market-cap snapshot is kept);
   - computes the concentration flag and the 24h most-mentioned ranking by distinct accounts;
   - writes `runs/run_<stamp>.json` and `runs/blocks_<stamp>.md`.
4. **Render the report:** `python3 picks.py --run runs/run_<stamp>.json --live-24h`. It scores every CA called this run plus any CA with 2+ distinct callers in the last 24h (`--live-24h` fetches fresh DexScreener/RugCheck data for those), writes `runs/report_<stamp>.md` and prints it. Add `--explain` to see each score breakdown on stderr (for you, not the report). Never pass `--dry-run` on a routine run: the normal run records what it posted in `posted_picks.json`, and that is how repeats are suppressed (use `--dry-run` only for tests). Send the output as-is; don't add sections or commentary. If you must fix something, edit `picks.py`, not the report.
5. **Deliver.** Send it to the owner in chat as usual (the same short text). If `/workspace/trenches/telegram/config.json` has `"enabled": true`, also post it with `python3 /workspace/trenches/telegram/tg.py send --file runs/report_<stamp>.md --require "Not financial advice"` and follow `telegram-report-delivery` (retry once; on a second failure tell the owner in chat). Never change the Telegram destination during a run.

## Report format (v4, exactly this, nothing else)
```
**Trenches picks · <h:mm PM> Dubai**
BTC $<price> (<24h%>) · ETH ... · SOL ...

**1. $TICKER** (<Chain>) · **<score>/10**
CA: [<full CA>](<pump.fun or dexscreener link>)
MC $<mc> · Liq $<liq>
Why: <one line, from the score inputs>.
Trend: <Up|Down|Sideways> (1h x%, 6h y%, 24h z%, 24h buys/sells b/s).
Why: ... / Risk: ... as above
(a re-post is titled "**n. Update: $TICKER**" and has a "Changed: <what moved>." line above Trend)
(up to 5 picks, highest score first)

Data: Hyperliquid, DexScreener, RugCheck, <time> Dubai.

Not financial advice.
```
If nothing new qualifies: the header, the market line, `No new picks this hour.` and `Not financial advice.` Nothing else (no Closest line, no Data line). If the X reads failed but 24h picks still qualify: `X read failed this hour; picks are from the last 24h of calls.` above the picks. If X failed and there are no candidates at all: `X read failed this hour, so there are no picks.` then `No new picks this hour.`

## No repeats + trend (owner request Oct 12, 2026: "don't repeat the same calls, understand the trend")
- `picks.py` keeps `/workspace/trenches/posted_picks.json`: per CA the ticker, MC, score, callers and time when last posted. Entries expire after 72h.
- A qualifying token (2+ callers, score 6+) is posted only if it was never posted (or its entry expired), OR since its last post its MC moved 25%+ either way, its score changed by 2+, or a new caller joined. Re-posts are labelled `Update` with a `Changed:` line.
- Trend comes from DexScreener 1h/6h/24h price change and 24h buys/sells: Up, Down or Sideways. A NEW pick in a clear downtrend (1h and 6h both negative and 24h sells > buys) is dropped; updates still go out with their trend shown.
- Don't hand-edit the state file except to seed it; `--seed` records every currently qualifying pick as posted without printing a report.

## Conviction score (0-10, implemented in `picks.py`; change the rules there, then here)
- **Callers (0-4):** distinct tracked accounts posting the CA in the last 24h: 1 = 1, 2 = 3, 3+ = 4. A post that reads as a warning (rug, scam, cluster, bundle, insiders, dump, avoid, honeypot, "cannot be analyzed"...) doesn't count as a call.
- **Liquidity (0-2):** DexScreener best pair: $100K+ = 2, $25K-100K = 1; minus 1 if liquidity is under 5% of MC.
- **Safety (0-2):** +1 mint and freeze revoked, not rugged, no RugCheck "danger" and no GoPlus honeypot-type flag; +1 top-10 holders (excl. pools) at 20% or less.
- **Age (0-1):** oldest pair at least 24h old.
- **Momentum (0-1):** 24h change above 0, 1h between -15% and +100%, and 24h buys >= sells when Musebook reports them.
- **Caps:** only one caller = max 5 (one account is one voice, so a pick needs at least two independent callers). A tracked account warned about it this run = max 3. Hard fail = max 2: rugged, honeypot or can't sell, mint/freeze authority live, RugCheck danger, top-10 over 30%, liquidity under $10K, or no DexScreener data.
- **Strict mode (owner choice):** a token is listed only with 2+ distinct callers in 24h AND score 6+. A single-caller token is never a pick (the old "Closest" near-miss line is gone).
- A pick needs 6+. Max 5 picks. The "Risk" line is the highest-priority issue: hard fail > warning > single caller > vertical 1h move > new pair > thin liquidity > 24h down > low LP lock.

## Rules
- **Linking:** each CA links to `https://pump.fun/coin/<CA>` when it's a Solana CA ending in `pump`, otherwise to `https://dexscreener.com/<chain>/<CA>`. Always print the full CA.
- **Sources:** one closing `Data:` line names the sources and time instead of per-figure labels. If a source didn't return a figure, the score treats it as missing (0 points), never estimated. DexScreener cached values (rate-limit fallback) still score, but say "cached" in the Data line.
- **Tally:** only CA mentions count; cashtag-only mentions can't be picks (no CA to verify). Posts listing 5+ tickers are screener dumps, not calls. `fetch.py build` still logs every CA to `calls.jsonl` and computes the concentration flag and 24h ranking in the run file; they feed the score but aren't printed.
- **Style:** short and clean, no tables, no sentiment paragraphs, Dubai time labelled. The owner asked for "what to buy" with a conviction score, so "No new picks this hour" and the score are allowed; still no price targets, sizes or "ape" language, and never "guaranteed"/"safe".
- **Quiet hours:** nothing new means "No new picks this hour." Never pad with old posts. If X reads failed, say so plainly.
- **Previous format:** the v3 long digest (sentiment, majors commentary, accumulating, fading, Calls & CAs, most mentioned) is backed up at `/workspace/trenches/backups/report-format-v3_20261009/SKILL.md`. Use it only if the owner asks for the long version.

## Track record, smart money, exits, scorecard (owner request Oct 12, 2026)
Code: `tracker.py` (callers, Nansen, exits) and `/workspace/calls/scorecard.py`; `picks.py` uses both automatically.
- **Each run, before step 4:** `python3 tracker.py callers --max-fetch 40` (resolves calls in `calls.jsonl` that are 24h+ old via GeckoTerminal hourly OHLCV; updates `callers.json`; takes ~5s per call, so cap it). Per handle+CA the first call counts. Hit = peak +50% within 24h of the call; also median 24h return. `python3 tracker.py show` prints the leaderboard.
- **Caller quality (score -1..+1):** callers with 3+ resolved calls count. +1 if their avg hit rate >= 50% and median 24h return > -30%; -1 if all hit < 20% or median 24h return <= -50%. The report shows `Callers: @x (hit 62%, med 24h -10%)`, `(new)` when under 3 resolved calls.
- **Smart money (score -1..+1):** Nansen `POST https://api.nansen.ai/api/v1/tgm/flow-intelligence` `{chain, token_address, timeframe:"1d"}` with header `apiKey: $NANSEN_API_KEY` (never print the key). Net = smart_trader + top_pnl + whale net flow. >= +$10K = +1, <= -$10K = -1 (and Risk "smart money net selling"). Line: `Smart money (24h): net buy $X (N wallets).` Only checked for 2+ caller, non-hard-fail tokens. Fails soft (no line, 0 bump) on errors or uncovered chains (e.g. Robinhood chain). `--no-nansen` disables.
- Score caps still apply after these bumps; max 10.
- **Exit alerts:** `posted_picks.json` entries live 7 days for this (repeat suppression still 72h). If MC is down 30%+ from the post MC, or liquidity down 40%+ from post liquidity (picks posted from Oct 12 on store `liq`), the report gets one line under the market line: `Exit: $TICKER (MC $a -> $b (-x%) since posted).` Once per token (`exit_alerted`). This line is part of the report; keep it.
- **Scorecard:** every non-dry-run picks.py post is recorded in `/workspace/calls/scorecard.json`. The report format above gains the optional `Exit:` lines, `Callers:` and `Smart money` lines; nothing else changes.
